# 对手如何决策

本次升级将原先的单次三选一，改为「模型判断 → 历史融合 → 规则推演 → 回合复盘」。仍使用 Laya 多语言原始权重，**没有进行专项微调，不宣称模型优于规则或达到最优博弈**。

## 一回合的数据流

1. `decision_context()` 只提取双方回合前属性、馆主性格、已结束回合数、最近六次玩家出招。输入不含请求里的 `action`、会话标识或上一轮分析正文。
2. Laya 一次批量回答两个 `choice` 问题：预测玩家会强攻/固守/挑逗；选择施压/留力/蓄势的战术目标。上下文限制 512 token，减小 CPU 服务内存和延迟。
3. 近期出招按新近程度加权，加入平滑先验和体力约束。模型预测分布占 35%，经验统计占 65%；模型权重不作胜率展示。玩家体力不足时，强攻预测权重归零。
4. 对每个合法候选招式，枚举玩家可能的三个招式，用共享的纯结算函数计算预期伤害、资源变化和进攻准备度。各馆主对进攻、防伤、体力、斗志有不同权重；模型战术目标调整这些权重。
5. 选择最高收益动作。馆主偶尔在差距不超过 2 分的候选招式中变招，幅度因性格不同。不会选择体力不足的强攻。
6. 双方同时结算后，才公布判断。复盘保存模型原始选择、融合预测、实际动作、各招收益与是否猜中。另给出无模型参考首选，说明模型是否真的改变收益排序。

三位馆主：急先锋重进攻，守拙翁重防伤与体力，听风客重斗志并有更多近似收益下的变招。性格本身不是隐藏加成，双方仍使用相同伤害与资源规则。

## 解释的边界

- 预测是对即将发生的回合的估计，不是读取玩家点击。揭晓时显示「依据前 N 回合」。
- 百分比是未校准的融合预测倾向，不是胜率。
- 战术文字由规则模板生成，不是模型思维过程或自然语言理由。
- 模型和规则可以意见一致；复盘会如实显示未改变首选，不把每一招的效果都归功于 Laya。
- 模型加载、忙碌、超时、异常时，使用同样具有历史记忆的规则策略，并明确给出降级原因。
- 记忆只在本局内存在，服务重启失效，不建立跨会话玩家画像。

## 验证

自动化测试覆盖：历史切换、预测合法性、人物差异、模型能改变实际择招、不可负担强攻、非法模型输出、降级来源、回合前数据隔离、同时结算对称性。可运行：

```sh
.venv/bin/python -m pytest -q
.venv/bin/python scripts/evaluate_strategy.py
```

`strategy-evaluation.json` 为固定脚本对手的诊断：四种打法、每种 40 个种子、三位馆主；比较旧随机规则与新记忆规则。**不调用 Laya，因此不用于证明 Laya 的收益。**各策略随机数消耗不同，不是逐次伤害完全配对的实验；结果不代表人类玩家胜率。其目的仅是确认新规则能处理固定打法、不同性格呈现不同动作分布。

### 真实模型接入诊断

`laya-smoke.json` 记录了本地 CPU 的 3 场固定出招序列、共 24 回合：24 回合均使用 Laya，6 回合的模型信号改变了无模型策略的首选排序。它验证模型输出确实影响选择，不证明这些改变更优，也不衡量对人类的胜率。测试没有固定对局随机种子，所以复测次数可能不同。
